# 竞品分析系统：搜索/抓取层免费方案落地（Tavily + 预取正文直通）

**时间**：2026-09-26

## 背景

王者荣耀等游戏竞品任务跑出「0 chunk → Analyzer [数据不足] → Quality 35分 → 改写死循环」，根因三层：
1. 搜索层：cn.bing.com 对游戏竞品 query 做 SEO 干预，前10条全是官网/下载页/应用商店/百科，捞不到点评文章
2. 抓取层：官网/点评平台是 SPA（JS 渲染），httpx 只拿到几十字符骨架，CJK<200 被门禁丢弃
3. 结果：0 chunk → 分析无数据

## 方案选型（用户已拍板「可以」，采纳免费组合）

- 搜索层：Tavily（1000次/月免费，AI Agent 专用，`include_raw_content` 直接返回渲染后正文）
- 兜底：保留 cn.bing（Tavily 额度用完降级）
- 抓取层：httpx 优先；Jina Reader（r.jina.ai）原计划兜底 SPA

## 实测连通性（2026-09-26 关键修正）

| 服务 | 结果 | 结论 |
|------|------|------|
| Tavily | ✅ 可达（HTTP 401 因假 key，线路通） | 核心方案成立 |
| Jina Reader | ❌ ConnectTimeout（境外线路不可达） | 免费抓 SPA 兜底废弃 |
| Sogou | ❌ DNS 失败 | 旧判断正确 |
| cn.bing | ✅ 200 | 兜底可用 |
| 硅基流动 | ✅ | embedding 不受影响 |

**关键调整**：Jina Reader 不可达，改为用 Tavily 的 `include_raw_content=True` 让 Tavily 服务端渲染并返回正文，一举解决「搜到点评 + 拿到正文」，绕开「搜到 URL → httpx 抓不到 SPA」死结。`jina_reader_enabled` 默认改为 False（保留开关）。

## 代码改动清单

1. **src/config.py**：新增 `tavily_api_key` / `tavily_enabled` / `tavily_max_results` / `jina_reader_enabled` 字段

   - `web_search` 增加 L0 Tavily 层（配 key 才启用），`include_raw_content=True`，结果加 `raw_content` 字段
   - 新增 `_jina_fetch()` 函数（保留但默认关闭）
   - `web_fetch` 增加 Jina 兜底块（受 `jina_reader_enabled` 控制）
3. **src/agents/collector.py**：
   - 分组时保存 `raw_content`
   - `_fetch_one` 优先用预取正文（CJK>=200 直通，跳过 web_fetch）
   - **修复 bug**：`_MIN_CJK_CHARS` 原为步骤4的局部变量，`_fetch_one`（步骤3）引用会 UnboundLocalError → 提升为模块级常量
